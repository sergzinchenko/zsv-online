Свой инструмент может обращаться к внутренним сервисам компании: порталу, системе заявок, API во внутренней сети. Запрос идёт через локальный хост, адрес которого задан в настройках. Приложение проверяет такой запрос так же, как запрос модели через прокси.

Ниже описано, как подготовить приложение, создать или переделать инструмент и что написать в навыке.

Подготовка#

  1. Откройте «Настройки → Локальный хост», укажите адрес прокси и нажмите «Сопрячь».
  2. Если сервис требует входа под учётной записью Windows (SSO), проверьте три условия из таблицы ниже.
Условие для SSOГде
Запущен Java-проксиNode-прокси вход Windows не поддерживает
Адрес сервиса есть в списке allowlistФайл config.properties прокси
Включена отметка «Разрешить режим SSO (доменная аутентификация)»«Настройки → Локальный хост»

Создать инструмент#

Удобнее поручить это агенту. Включите в чате навык «Эксперт по агенту» и опишите задачу: адрес сервиса, что передать, что вернуть, нужен ли вход Windows и к какому навыку отнести инструмент.

Создай инструмент intranet_items: получает заявки с https://intranet.example/api/items по параметру status через локальный хост, со входом Windows. Отнеси его к навыку «Внутренние сервисы».
  1. Агент создаст инструмент. Новый инструмент не работает, пока его код не проверен.
  2. Откройте инструмент на вкладке «Инструменты» и прочитайте код. Кнопка «🩺 Проверить с моделью» найдёт ошибки в заполненных полях.
  3. Отметьте «Код проверен» и сохраните.
  4. Включите навык инструмента в чате.

Без агента инструмент создаётся на вкладке «Инструменты»: имя, описание, параметры в виде JSON Schema, код, навыки и отметка «Код проверен».

Код инструмента#

Во внутреннюю сеть код обращается функцией agent_proxy_fetch. Обычный fetch к внутренним, локальным и приватным адресам не пропускается.

const status = String(params.status || 'open');
const r = await agent_proxy_fetch(
  'https://intranet.example/api/items?status=' + encodeURIComponent(status),
  { method: 'GET', sso: true });
if (!r.ok) return { error: r.error || ('HTTP ' + r.status), hint: r.hint };
const items = await r.json();
return { count: items.length, items: items.slice(0, 50), source: r.finalUrl || r.url };
ЧтоКак в agent_proxy_fetch
Адрес прокси и токен сопряженияВ коде не нужны: приложение берёт их из настроек
МетодыGET, POST, PUT, DELETE, PATCH, HEAD
Заголовки запросаТолько Content-Type и Authorization; с другими именами запрос не отправляется
Тело запросаСтрока или объект; объект отправляется как JSON
Заголовки ответаДоступен только Content-Type
Длина ответаДо 4 млн символов. Предел ответа инструмента из «Настроек» действует на то, что инструмент возвращает модели
ОтказОтвет с ok: false, error и hint; исключения нет
Адрес после редиректаПоле finalUrl
Вход WindowsПараметр sso: true

Настройка, которую вводят один раз#

Адрес сервиса, выбранную систему и другие настройки инструмент хранит в памяти агента функцией agent_memory. Это та же память, что открывается чипом «🧠 память» в панели чата. Она общая для всех чатов и попадает в резервную копию.

let url = await agent_memory.get('intranet.url');
if (!url) {
  const f = await agent_form({ title: 'Адрес сервиса', fields: [
    { name: 'url', label: 'Адрес', type: 'text', required: true }] });
  if (!f.submitted) return { error: 'Адрес сервиса не задан' };
  url = f.values.url;
  await agent_memory.set('intranet.url', url);
}
ЧтоКак в agent_memory
Прочитатьawait agent_memory.get(ключ); если записи нет, null
Записатьawait agent_memory.set(ключ, значение); ответ { ok: true } или { ok: false, error }
Удалитьawait agent_memory.remove(ключ)
Список ключейawait agent_memory.list('intranet.')
КлючЛатиница, цифры, _ и -, части через точку: intranet.url. Записи модели без точки инструменту не видны
ЗначениеЛюбое значение JSON до 64 КБ

Не храните в памяти пароли и ключи: её видят модель и пользователь. В режиме «Максимальный» каждую запись подтверждает пользователь.

Вход по паролю#

Если сервис пускает только по имени пользователя и паролю (вход Basic), инструмент просит приложение открыть окно входа функцией agent_secret. Пароль вводится в окне приложения с замком 🔐 в заголовке и хранится зашифрованным. Код инструмента и агент пароля не видят: в запрос его подставляет приложение, и только к серверу, для которого его ввели. Адрес сервера должен начинаться с https://: по http пароль не отправляется.

const KEY = 'intranet.login';
const SERVER = 'https://intranet.example';
if (!(await agent_secret.has(KEY)).exists) {
  const login = await agent_secret.ask(KEY, { url: SERVER, title: 'Вход в intranet.example' });
  if (!login.ok) return { error: login.cancelled ? 'Пароль не введён' : login.error };
}
const r = await agent_proxy_fetch(SERVER + '/api/items', { auth: KEY });
if (r.status === 401) await agent_secret.remove(KEY);
ЧтоКак в agent_secret
Спросить входawait agent_secret.ask(ключ, { url, title, user }); ответ { ok: true, user }, { ok: false, cancelled: true } или { ok: false, error }
Проверить, есть ли входawait agent_secret.has(ключ); ответ { exists, user }
Забыть входawait agent_secret.remove(ключ)
Запрос со входомagent_proxy_fetch(адрес, { auth: ключ }); без sso. К другому серверу, порту или по http запрос с этим входом не уйдёт

Пароли входов в резервную копию не попадают: после восстановления их вводят заново. Если сервис ответил 401, не повторяйте запрос с тем же паролем: многие системы блокируют пользователя после нескольких неверных паролей. Удалите вход, и следующий вызов спросит его заново.

Файл для анализа агентом#

Выгрузку, которую агенту предстоит анализировать, инструмент кладёт в артефакт чата функцией agent_artifact. Файл хранится в чате вне переписки, под вызовом появляется кнопка «скачать ещё раз». Агент берёт файл по artifact_id: sandbox_run получает его в папку input/, table_query считает по нему итоги, export_xlsx делает книгу Excel. Содержимое файла модель видит, только когда сама его читает.

const a = await agent_artifact({ name: 'orders.csv', content: csv, mime: 'text/csv' });
return { rows: count, artifact_id: a.artifact_id,
  download: [{ artifact_id: a.artifact_id, filename: a.filename }] };
ЧтоКак в agent_artifact
Положить файлawait agent_artifact({ name, content, mime }); ответ { ok: true, artifact_id, filename, bytes }, отказ — исключение
Заодно скачатьdownload: true
Двоичный файлcontent в base64 и base64: true
Кнопка скачивания под вызовомВерните download: [{ artifact_id, filename }] в результате инструмента
Только скачать, без артефактаagent_download

CSV при скачивании и во входе sandbox_run получает метку BOM, чтобы Excel открыл кириллицу; в Python такой файл читается с encoding="utf-8-sig".

Переделать существующий инструмент#

Инструмент, который обращается к внутреннему адресу через fetch, получает ошибку с подсказкой про agent_proxy_fetch.

  1. Замените вызовы fetch к внутренним адресам на agent_proxy_fetch. Запросы к открытым адресам в интернете можно оставить на fetch.
  2. Проверьте разбор ответа: заголовки, отказы и параметр sso.
  3. Правку можно поручить агенту: «Переделай инструмент intranet_items: запросы к intranet.example через agent_proxy_fetch». Агент сначала читает код инструмента и меняет только нужные фрагменты; разницу «было → стало» он покажет в ответе.
  4. Правка кода снимает отметку «Код проверен». Проверьте код и отметьте её снова. Запомненное разрешение SSO для этого инструмента тоже сбрасывается.

Навык#

Навык подсказывает модели, когда вызывать инструмент. В тексте навыка укажите:

  • какие данные даёт инструмент и когда его вызывать;
  • что за этими данными не нужно обращаться через proxy_fetch;
  • что вход Windows подтверждает пользователь.
Данные о заявках бери инструментом intranet_items. Не обращайся к intranet.example через proxy_fetch: инструмент знает адрес и формат ответа.

Текст навыка меняется на вкладке «Навыки» или просьбой в чате. Изменение состава навыка агентом всегда подтверждает пользователь.

Что подтверждает пользователь#

Режим безопасностиОбычный запросЗапрос со входом Windows
«Оптимальный»Вопрос о новом адресе; ответ можно запомнитьВопрос каждый раз
«Максимальный»Вопрос о новом адресе; если задан список разрешённых адресов, остальные запрещеныВопрос каждый раз
«Минимальный», «Отключено»Без вопросаВопрос; можно отметить «Больше не спрашивать» для этого инструмента и адреса

В окне подтверждения указан инструмент, который делает запрос. Каждый запрос попадает в журнал безопасности. Отметка «Больше не спрашивать» действует до перезагрузки страницы. Она сбрасывается при переходе в более строгий режим и после правки кода инструмента. Запрос со входом Windows, который модель делает сама через proxy_fetch, подтверждается каждый раз в любом режиме.

Советы#

  • Один инструмент на один сервис: адрес, параметры и разбор ответа находятся в одном месте.
  • Включайте sso: true только для сервисов, которые требуют входа Windows.
  • Возвращайте error и hint из ответа как есть: по ним агент объяснит причину отказа.
  • Возвращайте только нужные поля и ограничивайте число записей: большой ответ занимает контекст модели.
  • Не передавайте ключи и пароли в параметрах инструмента и в тексте навыка.
  • Проверяйте код перед отметкой «Код проверен», даже если его написал агент.
