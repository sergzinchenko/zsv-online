Локальный хост: настройка и запуск прокси

Локальный хост (прокси) — небольшая программа на вашем компьютере. Через неё инструмент proxy_fetch и инструмент agent_proxy_fetch обращаются к адресам, которые браузер сам открыть не может: внутренним сервисам компании и сайтам без разрешения CORS. Без прокси эти инструменты не работают, остальные возможности приложения от него не зависят.

Прокси нужен, если вы хотите, чтобы агент:

  • читал внутренний портал, вики или систему заявок;
  • вызывал внутренний API;
  • заходил на ресурс под вашей учётной записью Windows (SSO).

Что это за программа#

Прокси — это proxy-sso.jar, программа на Java. Нужны Windows, Java 8 или новее и лицензия прокси. Настройки лежат в файле config.properties. Агент релиза 39 работает с прокси, поддерживающим протокол 4 (Java-прокси 3.2.0). Сам агент без прокси лицензии не требует.

Быстрый путь: готовый комплект из приложения#

  1. Откройте «Настройки → Локальный хост».
  2. Нажмите «📦 Сгенерировать файлы прокси».
  3. Заполните поля (подсказки к ним — ниже) и подтвердите.
  4. Выберите пустую папку. Приложение сохранит в неё сам прокси, файл настроек и скрипты запуска: start-proxy.bat для Windows и start-proxy.sh для оболочки sh. Лицензирование требует Windows.
  5. Если выбор папки недоступен, комплект скачается одним архивом. Распакуйте его в отдельную папку.
  6. Запустите start-proxy.bat двойным щелчком.
  7. Установите лицензию по следующему разделу и выполните сопряжение.

Отметка «Прописать адрес прокси в настройках агента» уже стоит: адрес http://127.0.0.1:<порт> попадёт в поле «Адрес прокси» сам.

Запуск вручную#

Если файлы уже есть, генератор не нужен.

Положите рядом proxy-sso.jar и config.properties и выполните в этой папке:

java -Dconfig.file=config.properties -jar proxy-sso.jar

Окно с прокси оставьте открытым: пока оно работает, работает и прокси. Остановка — Ctrl+C.

При успешном старте прокси печатает строку вида proxy-sso v3.2.0 слушает http://127.0.0.1:3000. Адрес http://127.0.0.1:3000/health показывает версию, протокол 4, состояние license.state и число сопряжённых агентов pairing.paired. Без лицензии процесс запускается для её установки, но запросы не пересылает. Если в настройках ошибка, прокси сообщает, какое значение исправить.

Java-прокси с версии 3.1.1 отключает выделение мышью в окне консоли на время работы и не зависает, если вывод остановлен. У более старых версий выделение текста или клавиша Pause останавливает программу, пока вы не нажмёте Enter или Esc. Вернуть выделение можно ключом console.quickEdit=true.

Минимальный файл настроек#

Файл config.properties:

bindAddress=127.0.0.1
port=3000
allowlist=intranet.example.local
pairing.required=true

Остальные значения подходят по умолчанию. Менять настройки можно в любой момент, после правки перезапустите прокси.

Установка и продление лицензии#

  1. На компьютере с запущенным прокси откройте http://127.0.0.1:3000/license (при другом порте измените адрес).
  2. Для личной установки скопируйте код запроса и передайте разработчику вместе с адресом агента. Код содержит открытый ключ, имя компьютера и пользователя. Для корпоративной установки получите лицензию и комплект ключа прокси у администратора; файл proxy-key.json лежит рядом с настройками.
  3. На странице /license выберите полученный license.json и нажмите «Установить лицензию». Дождитесь сообщения об успешной установке. Перезапуск не нужен.
  4. Вернитесь в «Настройки → Локальный хост» и нажмите «Проверить прокси». Видны номер лицензии, заказчик и срок. За 30 дней появляется предупреждение о продлении. Эти сведения также показаны в окне истории доработок по значку релиза.

Для продления установите новый файл тем же способом. Неверный файл не заменяет действующую лицензию. После даты окончания запросы через прокси прекращаются, в том числе в уже сопряжённом агенте; отсрочки нет. Остальные возможности агента продолжают работать.

Личная лицензия привязана к ключу Windows-пользователя на этом компьютере. После переустановки или переноса на другой компьютер получите новый код запроса. Не удаляйте %LOCALAPPDATA%\proxy-sso\license-state.dat: в нём защищённый ключ и контроль времени. Корпоративная лицензия дополнительно проверяет членство компьютера в указанном домене Windows.

Адрес приложения, включая схему и порт, должен быть в лицензии. Переезд на другой адрес требует новой лицензии. Для проверки подписи открывайте агент по HTTPS или на localhost. Лицензия хранится у прокси; её отдельная установка в браузер не нужна.

Лицензия при работе#

В обычной работе лицензия не требует действий. Прокси проверяет её сам, агент — перед отправкой данных.

Если лицензия не покрывает запрос, агент пишет причину в ответе чата: истёк срок, адрес приложения не включён в лицензию, нет нужной функции, прокси устарел или не отвечает. Разбор причин и что делать — в таблице ошибок ниже. Срок и предупреждение о продлении видны в «Настройках → Локальный хост» и в окне истории доработок.

Инструменты без прокси работают как раньше: расчёты на Python, файлы, заметки, переписка с моделью.

Первое подключение#

  1. Запустите прокси.
  2. В приложении откройте «Настройки → Локальный хост». В поле «Адрес прокси» впишите адрес, например http://127.0.0.1:3000, если генератор не сделал этого сам.
  3. Нажмите «🔌 Проверить прокси». Должно появиться «Прокси отвечает, версия …».
  4. В блоке «Сопряжение» нажмите «🔗 Сопрячь». Приложение покажет короткий код.
  5. Откроется окно прокси с таким же кодом. Сверьте коды и нажмите «Разрешить». Код действует две минуты, потом сопряжение придётся начать заново. Окно должно открыться из агента: страница, открытая вручную по ссылке, ответит «Окно агента не найдено».
  6. Состояние сопряжения в приложении изменится на подтверждённое. Теперь запросы агента будут проходить.

Сопряжение выполняется один раз. Прокси запоминает только хэш токена, в файле pairings.tsv (по умолчанию в %LOCALAPPDATA%\proxy-sso\). Чтобы отозвать все сопряжения, удалите этот файл или нажмите «Отменить сопряжение».

Пока прокси не сопряжён, он отвечает на запросы отказом. Это защита: иначе любая программа на компьютере могла бы ходить через прокси, в том числе под вашей учётной записью.

Вход под учётной записью Windows (SSO)#

SSO работает только в Java-прокси на Windows. В лицензии должна быть функция sso. Также нужны три условия одновременно:

  1. Запущен Java-прокси.
  2. Сервер есть в allowlist. Указывайте полное имя (intranet.example.local), а не IP-адрес. При пустом allowlist прокси отклоняет SSO-запрос кодом SSO_NOT_ALLOWED, а сервер вне непустого списка — кодом TARGET_NOT_ALLOWED.
  3. В «Настройках → Локальный хост» отмечено «Разрешить режим SSO (доменная аутентификация)».

По умолчанию прокси использует только Kerberos. Если сервер Kerberos не предлагает, прокси откажет с кодом SSO_SCHEME_NOT_OFFERED. Переход на NTLM включается отдельно: генератор, поле «Разрешить NTLM», или sso.allowNtlm=true в config.properties.

В режиме SSO прокси обращается к серверу от имени вашей учётной записи, и сервер видит, кто вы. Адрес выбирает модель, поэтому держите allowlist узким.

Вход в приложение и защита от CSRF#

Многие внутренние приложения (на Spring Security, GWT и подобных) связывают токен защиты от CSRF с cookie сеанса. Браузер агента cookie чужого сайта не хранит, поэтому прокси ведёт их сам (Java-прокси 3.1.1 и новее). Страница, открытая первым запросом, и следующий POST с токеном идут в одном сеансе.

  • Сеанс принадлежит агенту, серверу и учётной записи. Сеанс другого агента или другой учётки не подмешивается.
  • Cookie сайта агенту не отдаются, они остаются в прокси. Свой заголовок Cookie из запроса прокси не смешивает с сеансом.
  • Токен страницы агент передаёт сам: в заголовке X-CSRF-Token, X-XSRF-Token или в теле формы (_csrf=...). Cookie XSRF-TOKEN сеанса прокси переносит в X-XSRF-TOKEN изменяющего запроса, если заголовок не задан.
  • Сеанс забывается через 15 минут без запросов. Время задаёт session.idleSec. Сеансы отключаются ключом session.cookies=off в config.properties.

Если приложение отвечает «Could not verify the provided CSRF token because your session was not found», проверьте версию прокси в окне запуска: у Java-прокси 3.1.0 и старше сеанс вне серверов SAP не сохраняется. Обновите прокси: заново сгенерируйте файлы или возьмите proxy-sso.jar из поставки.

Корпоративный сертификат#

Если внутренний сервис использует сертификат корпоративного центра, прокси может ответить ошибкой проверки сертификата. Правильное решение: добавить корневой сертификат в хранилище.

РежимКогда
SYSTEM_DEFAULTСертификаты проверяются по хранилищу Java. Подходит для публичных сайтов
CUSTOM_CAСвоё хранилище с корпоративным корнем. Рекомендуется для внутренних сервисов
INSECURE_TRUST_ALLСертификаты не проверяются. Только чтобы быстро убедиться, что дело в сертификате

Для CUSTOM_CA укажите путь к хранилищу (.jks, .p12, .pfx) и пароль. В файле config.properties пишите путь с прямыми слэшами: C:/tools/truststore.jks.

Если публичные сайты не открываются с ошибкой PKIX path building failed, а в браузере открываются, у вас старая сборка Java 8 с устаревшим хранилищем. Поставьте свежую сборку Java 8 (Adoptium, Corretto) или подложите актуальное хранилище через CUSTOM_CA.

SAP#

Серверы SAP принимают изменяющие запросы только с токеном CSRF в рамках сеанса. Для SAP-профиля нужна функция sap в лицензии. Впишите хост SAP в «Хосты SAP» (sap.hosts) и в белый список. Для других серверов этот режим не нужен.
