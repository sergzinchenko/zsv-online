# Naumen Service Desk

Чтение данных Naumen Service Desk через REST API: заявки, сотрудники, подразделения и другие объекты. Только чтение.

## Навыки пакета

| Навык | Версия | Что делает | Инструменты |
|---|---|---|---|
| Naumen SD: серверы | 1.0.5 | Справочник серверов Naumen Service Desk, текущий сервер для всех чатов, вход Windows или логином и паролем Naumen, проверка связи с REST API | `sd_system` (запись), `sd_check` (чтение) |
| Naumen SD: чтение данных | 1.2.1 | Поиск объектов Naumen Service Desk по классу и значениям атрибутов, чтение одного объекта по идентификатору в компактном виде: заявки, сотрудники, подразделения. Учитывает выясненное о сервере: рецепты запросов, названия значений вместо идентификаторов | `sd_find` (чтение), `sd_get` (чтение) |
| Naumen SD: исследование и знания | 1.1.1 | Исследование незнакомых классов Naumen SD и память о сервере: смысл атрибутов, справочники значений, рецепты запросов, профили классов; поиск по выясненному; сводки по значениям атрибута | `sd_knowledge` (чтение), `sd_describe` (чтение), `sd_learn` (запись), `sd_profile` (запись), `sd_summary` (чтение) |

Пакет 1.0.0, архив `naumen-sd-1.0.0.json`. Из поставки ставятся отмеченные навыки, импортом архива — все навыки пакета.

## Данные

- «Naumen SD: серверы и знания» (ключи `sd.*`): Справочник серверов Naumen SD, текущий сервер и то, что агент выяснил о сервере: классы, смысл атрибутов, справочники значений, рецепты запросов. Пишут инструменты пакета; модель читает через sd_knowledge. С навыком переносится `sd.kb.*`, `sd.schema.*`, `sd.dict.*`, `sd.profiles`, остальное личное.

## Важно знать

- Справочник серверов и текущий сервер хранятся в памяти агента: sd.systems, sd.current (один текущий сервер на весь агент). Любой инструмент пакета при первом вызове сам спросит сервер формой.
- Запросы идут методом GET к REST API Naumen (адрес вида https://сервер/sd/services/rest/...) через локальный хост. Вход Windows (SSO) нужен Java-прокси, сопряжённый с агентом, сервер Naumen в его allowlist и отметка «Разрешить SSO» в «Настройки → Локальный хост». Вход логином и паролем Naumen: пароль вводится в окне приложения при первом запросе и хранится зашифрованным, в резервную копию не попадает; адрес должен быть https.
- Ответ Naumen для запросов весит десятки килобайт (около 400 атрибутов), поэтому инструменты сжимают его и по умолчанию читают набор атрибутов класса: профиль из знаний о классе (sd.kb.*), встроенный набор или title.
- Выясненное о сервере агент запоминает в памяти, по ключу на класс и справочник: название и типы класса, смысл атрибутов, справочники значений (приоритеты, услуги, команды), рецепты удачных запросов, состав атрибутов по образцам. Справочники элементов с кодом пополняются сами при чтении, остальное — навыком «исследование и знания» (sd_learn). Поиск переводит названия значений в идентификаторы по справочнику и выполняет рецепты. Сотрудники и запросы в справочники не попадают. Профили прежних версий (sd.profiles) переезжают в знания о классе сами.
- Ключ доступа (accessKey) пакет не использует: инструмент не видит секретов, а ключ пришлось бы подставлять в адрес.
- Навыкам пакета нужна сборка Camomile r36 с папкой content и входом по паролю для инструментов (agent_secret) или новее.
- Интерфейс самого приложения Naumen (GWT) через агента недоступен: его запросы собираются кодом страницы. Используйте REST API.

## После установки

Навыки и инструменты пакета подписаны разработчиком. Код инструментов не показывается и не меняется, отметка «Код проверен» не нужна. Навыки пакета можно смотреть и включать в чатах, но не менять. Новая версия ставится из поставки.

Включите нужный навык в чате. Запуск инструмента подтверждается по его категории: чтение в режиме «Оптимальный» идёт без вопросов, удаление подтверждается во всех режимах, кроме «Отключено».
