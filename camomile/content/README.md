# Навыки для импорта

Пакеты навыков с инструментами, по одному архиву на пакет. Они выходят отдельно от релизов Camomile и ставятся обычным импортом.

## Установка

С релиза 38: вкладка «Навыки» → «📚 Из поставки» → пакет. Прочитайте описание, отметьте нужные навыки и «Описание прочитано», нажмите «Установить». Пароль вводить не нужно.

Вручную:

1. Вкладка «Навыки» → «📥 Импорт» → архив пакета, пароль пакета. Ставятся все навыки пакета с инструментами и разделами памяти.
2. Включите навык в чате. Инструменты с подписью разработчика (пометка «🔏 разработчик») работают сразу. У остальных откройте код, прочитайте и отметьте «Код проверен».

В Camomile до r38 инструменты ставятся вторым импортом: вкладка «Инструменты» → «📥 Импорт» → тот же архив и пароль.

Новая версия пакета ставится так же, в режиме «Перезаписать элементы с совпадающими id». Включённость навыков в чатах сохраняется, записи памяти остаются.

## Confluence

Корпоративный Confluence Server или Data Center через REST API: поиск, чтение, правка страниц, метки, комментарии и вложения.

Архив: `confluence-1.0.0.json`, пароль: `camomile-confluence`. Инструменты лежат в папке «Confluence», навыки — в папке «Прикладные / Confluence».

| Навык | Версия | Инструменты |
|---|---|---|
| Confluence: серверы | 1.0.0 | `confluence_system`, `confluence_status` |
| Confluence: чтение | 1.0.0 | `confluence_list_spaces`, `confluence_list_pages`, `confluence_search`, `confluence_get_page`, `confluence_attachments` |
| Confluence: правка | 1.0.0 | `confluence_convert_markup`, `confluence_create_page`, `confluence_update_page`, `confluence_delete_page`, `confluence_labels`, `confluence_comments` |

Данные навыков: раздел памяти «Confluence: серверы» (ключи `confluence.*`). Их видят только инструменты навыков пакета. Все записи личные, при переносе навыка не выгружаются.

Справочник серверов и текущий сервер хранятся в памяти агента: confluence.systems, confluence.current (один текущий сервер на весь агент). Любой инструмент пакета при первом вызове сам спросит сервер формой.

Запросы идут к REST API Confluence (адрес вида https://сервер/rest/api/...) через локальный хост. Вход: личный токен (Personal Access Token), логин и пароль или вход Windows (SSO). Токен и пароль вводятся в окне приложения при первом запросе, хранятся зашифрованными и в резервную копию не попадают; адрес должен быть https. Входу Windows нужен Java-прокси, сопряжённый с агентом, сервер Confluence в его allowlist и отметка «Разрешить SSO» в «Настройки → Локальный хост».

До релиза 38 Confluence был встроенным. Адрес и токен из прежних настроек переносятся в справочник серверов сами, как только пакет поставлен.

Навыкам пакета нужна сборка Camomile r38 или новее.

## Exchange

Корпоративная почта Microsoft Exchange через EWS: письма, календарь, адресная книга, отправка писем и приглашений с подтверждением.

Архив: `exchange-1.0.0.json`, пароль: `camomile-exchange`. Инструменты лежат в папке «Exchange», навыки — в папке «Прикладные / Exchange».

| Навык | Версия | Инструменты |
|---|---|---|
| Exchange: серверы | 1.0.2 | `ex_system`, `ex_check` |
| Exchange: почта | 1.0.2 | `ex_folders`, `ex_mail_find`, `ex_mail_get`, `ex_attachment` |
| Exchange: календарь | 1.0.2 | `ex_calendar`, `ex_event_get`, `ex_availability`, `ex_rooms` |
| Exchange: адресная книга | 1.0.2 | `ex_people`, `ex_group` |
| Exchange: отправка | 1.0.2 | `ex_mail_send`, `ex_meeting_create` |

Данные навыков: раздел памяти «Exchange: серверы» (ключи `ex.*`). Их видят только инструменты навыков пакета. Все записи личные, при переносе навыка не выгружаются.

Справочник серверов и текущий сервер хранятся в памяти агента: ex.systems, ex.current (один текущий сервер на весь агент). Любой инструмент пакета при первом вызове сам спросит сервер формой.

Запросы идут методом POST к Exchange Web Services (адрес вида https://сервер/EWS/Exchange.asmx) через локальный хост. Вход Windows (SSO) нужен Java-прокси, сопряжённый с агентом, сервер Exchange в его allowlist и отметка «Разрешить SSO» в «Настройки → Локальный хост». Если Exchange не принимает Kerberos, в config.properties прокси нужен sso.allowNtlm=true. Вход логином и паролем: пароль вводится в окне приложения при первом запросе и хранится зашифрованным, в резервную копию не попадает; адрес должен быть https.

Чтение ничего не меняет в ящике: письма не помечаются прочитанными. Отправка письма и приглашения идёт только после подтверждения в окне, где пользователь видит и правит адресатов и текст.

Нужен Exchange 2010 SP2 или новее (2013, 2016, 2019) с включёнными Exchange Web Services.

Навыкам пакета нужна сборка Camomile r36 с папкой content и входом по паролю для инструментов (agent_secret) или новее.

## Naumen Service Desk

Чтение данных Naumen Service Desk через REST API: заявки, сотрудники, подразделения и другие объекты. Только чтение.

Архив: `naumen-sd-1.0.0.json`, пароль: `camomile-naumen-sd`. Инструменты лежат в папке «Naumen SD», навыки — в папке «Прикладные / Naumen SD».

| Навык | Версия | Инструменты |
|---|---|---|
| Naumen SD: серверы | 1.0.5 | `sd_system`, `sd_check` |
| Naumen SD: чтение данных | 1.2.1 | `sd_find`, `sd_get` |
| Naumen SD: исследование и знания | 1.1.1 | `sd_knowledge`, `sd_describe`, `sd_learn`, `sd_profile`, `sd_summary` |

Данные навыков: раздел памяти «Naumen SD: серверы и знания» (ключи `sd.*`). Их видят только инструменты навыков пакета. С навыком переносится `sd.kb.*`, `sd.schema.*`, `sd.dict.*`, `sd.profiles`, остальное личное.

Справочник серверов и текущий сервер хранятся в памяти агента: sd.systems, sd.current (один текущий сервер на весь агент). Любой инструмент пакета при первом вызове сам спросит сервер формой.

Запросы идут методом GET к REST API Naumen (адрес вида https://сервер/sd/services/rest/...) через локальный хост. Вход Windows (SSO) нужен Java-прокси, сопряжённый с агентом, сервер Naumen в его allowlist и отметка «Разрешить SSO» в «Настройки → Локальный хост». Вход логином и паролем Naumen: пароль вводится в окне приложения при первом запросе и хранится зашифрованным, в резервную копию не попадает; адрес должен быть https.

Ответ Naumen для запросов весит десятки килобайт (около 400 атрибутов), поэтому инструменты сжимают его и по умолчанию читают набор атрибутов класса: профиль из знаний о классе (sd.kb.*), встроенный набор или title.

Выясненное о сервере агент запоминает в памяти, по ключу на класс и справочник: название и типы класса, смысл атрибутов, справочники значений (приоритеты, услуги, команды), рецепты удачных запросов, состав атрибутов по образцам. Справочники элементов с кодом пополняются сами при чтении, остальное — навыком «исследование и знания» (sd_learn). Поиск переводит названия значений в идентификаторы по справочнику и выполняет рецепты. Сотрудники и запросы в справочники не попадают. Профили прежних версий (sd.profiles) переезжают в знания о классе сами.

Ключ доступа (accessKey) пакет не использует: инструмент не видит секретов, а ключ пришлось бы подставлять в адрес.

Навыкам пакета нужна сборка Camomile r36 с папкой content и входом по паролю для инструментов (agent_secret) или новее.

Интерфейс самого приложения Naumen (GWT) через агента недоступен: его запросы собираются кодом страницы. Используйте REST API.

## SAP ADT

Чтение объектов ABAP через SAP ABAP Development Tools (ADT): поиск и пакеты, исходный код, словарь и CDS, транспорты, данные таблиц.

Архив: `sap-adt-1.0.0.json`, пароль: `camomile-sap-adt`. Инструменты лежат в папке «SAP ADT», навыки — в папке «Прикладные / SAP ADT».

| Навык | Версия | Инструменты |
|---|---|---|
| SAP: системы | 1.1.2 | `sap_system`, `sap_check` |
| ADT: поиск и пакеты | 1.0.2 | `adt_search`, `adt_package`, `adt_object_info` |
| ADT: исходный код | 1.0.2 | `adt_source`, `adt_object_structure`, `adt_message_class` |
| ADT: словарь и CDS | 1.0.2 | `adt_ddic`, `adt_cds` |
| ADT: транспорты | 1.0.2 | `adt_transports`, `adt_transport` |
| ADT: данные | 1.2.2 | `adt_table_data`, `adt_sql` |

Данные навыков: раздел памяти «SAP: системы и настройки» (ключи `sap.*`). Их видят только инструменты навыков пакета. Все записи личные, при переносе навыка не выгружаются.

Справочник систем и мандантов и текущая запись хранятся в памяти агента: sap.systems, sap.current (одна запись на весь агент), sap.settings (язык и вход Windows, общие для всех систем). Любой инструмент пакета при первом вызове сам спросит систему формой.

Запросы идут методом GET через локальный хост. Запись без манданта («S4D») — мандант системы по умолчанию и вход Windows: нужен Java-прокси, сопряжённый с агентом, хост SAP в его allowlist и отметка «Разрешить SSO» в «Настройки → Локальный хост». Запись с мандантом («S4D/200») — вход пользователем SAP: пароль вводится в окне приложения при первом запросе и хранится зашифрованным, в резервную копию не попадает.

Навыкам пакета нужна сборка Camomile r36 с папкой content и входом по паролю для инструментов (agent_secret) или новее.

Навыку «ADT: данные» нужен Java-прокси 3.1.0 или новее с хостом SAP в sap.hosts (config.properties прокси): чтение данных в ADT идёт через POST, CSRF-токен и сеанс SAP ведёт прокси.

В режиме безопасности «Оптимальный» спрашивается каждый запуск кода инструмента и каждый запрос со входом Windows. В режимах «Минимальный» и «Отключено» запуск не спрашивается, а вход Windows можно разрешить для инструмента до перезагрузки страницы.

## xWiki

Корпоративная xWiki через REST API: поиск, чтение, правка и история страниц, комментарии, вложения, объекты и таблицы LiveTable.

Архив: `xwiki-1.0.0.json`, пароль: `camomile-xwiki`. Инструменты лежат в папке «xWiki», навыки — в папке «Прикладные / xWiki».

| Навык | Версия | Инструменты |
|---|---|---|
| xWiki: серверы | 1.0.0 | `xwiki_system`, `xwiki_status`, `xwiki_list_wikis` |
| xWiki: чтение | 1.0.0 | `xwiki_list_spaces`, `xwiki_list_pages`, `xwiki_search`, `xwiki_get_page`, `xwiki_history`, `xwiki_attachments` |
| xWiki: правка | 1.0.0 | `xwiki_create_page`, `xwiki_update_page`, `xwiki_delete_page`, `xwiki_comments`, `xwiki_objects` |
| xWiki: таблицы | 1.0.0 | `xwiki_classes`, `xwiki_livetable` |

Данные навыков: раздел памяти «xWiki: серверы» (ключи `xwiki_srv.*`). Их видят только инструменты навыков пакета. Все записи личные, при переносе навыка не выгружаются.

Данные навыков: раздел памяти «xWiki: справочники таблиц» (ключи `xwiki.*`). Их видят только инструменты навыков пакета. С навыком переносится `xwiki.livetable.*`, остальное личное.

Справочник серверов и текущий сервер хранятся в памяти агента: xwiki_srv.systems, xwiki_srv.current (один текущий сервер на весь агент). В записи сервера — имя вики по умолчанию: на одной установке xWiki их бывает несколько. Любой инструмент пакета при первом вызове сам спросит сервер формой.

Запросы идут к REST API xWiki (адрес вида https://сервер/xwiki/rest/...) через локальный хост. Вход: логин и пароль xWiki или вход Windows (SSO). Пароль вводится в окне приложения при первом запросе, хранится зашифрованным и в резервную копию не попадает; адрес должен быть https. Входу Windows нужен Java-прокси, сопряжённый с агентом, сервер xWiki в его allowlist и отметка «Разрешить SSO» в «Настройки → Локальный хост».

Состав классов и колонок таблиц LiveTable инструмент xwiki_classes запоминает сам (xwiki.livetable.*): следующий запрос к тому же классу не ходит на сервер. Справочник переносится вместе с навыком.

До релиза 38 xWiki была встроенной. Адрес, имя вики, пользователь и пароль из прежних настроек переносятся в справочник серверов сами, как только пакет поставлен; справочники таблиц остаются на месте.

Навыкам пакета нужна сборка Camomile r38 или новее.
